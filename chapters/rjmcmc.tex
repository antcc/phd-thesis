\chapter{Reversible jump sampler implementation}\label{ch:rjmcmc}
%*****************************************

The methodological exposition in Chapter~\ref{ch:functional-regression} and Chapter~\ref{ch:functional-testing} introduced \acs{RJMCMC} as the core mechanism for posterior approximation in the Bayesian models proposed there. We now focus on the implementation details of this algorithm, together with a brief overview of the theoretical foundations.

Originally envisioned for inference in Bayesian mixtures, the \acs{RJMCMC} technique can be used to obtain approximate posterior samples in models with an unknown number of components, allowing joint inference on the parameters and the dimension itself. This is achieved by constructing a transdimensional Markov chain whose stationary distribution is the intended posterior, through a function that is proportional to it. The basis of the \acs{RJMCMC} mechanism, proposed by~\citet{green1995reversible}, is a clever reformulation of the standard \acf{MCMC} algorithm: on each iteration, apart from updating the current parameters, it tries to increase or decrease the dimension, creating new components or eliminating some already present. The acceptance fraction for these new moves is selected so that detailed balance as a whole is maintained, but this includes the possibly challenging computation of a certain Jacobian that is the key to dimension matching. However, in nested models such as ours, we can simplify this expression by only allowing on each iteration either the birth of a new component or the death of an existing one (i.e.~changing the dimension by one unit at a time). If we also make the proposal distribution for the newly birthed components independent of previous values, the Jacobian term disappears, and the acceptance fraction simplifies considerably \citep{richardson1997bayesian}. Taking the functional regression model in Chapter~\ref{ch:functional-regression} as an example, the acceptance probability of adding a new component is given by
\[
  \alpha_\text{birth} = \min\left\{1,\, \frac{L(Y \mid X, \theta_{p+1})}{L(Y\mid X, \theta_p)}\frac{\Pi(\theta_{p+1})}{\Pi(\theta_p)}\frac{d_{p+1, p}}{b_{p, p+1}}\frac{r_{\text{delete}}(p)}{r_{\text{select}}(p)}\frac{1}{q(\theta_{+1})}\right\}.
\]
Here \(p\) is the current number of components, \(b_{p, p+1}\) is the probability of increasing the dimension from \(p\) to \(p+1\) (birth), \(d_{p+1, p}\) is the probability of the reverse move (death), \(r_{\text{delete}}(p)=1/(p+1)\) is the reverse probability of deleting an existing component at random, \(r_{\text{select}}(p)=1/(P_{\max} - p)\) is the probability of selecting a particular inactive component to become active, \(q(\theta_{+1})\) is the proposal distribution for the added source, \(\Pi\) is the prior probability and \(L\) represents the likelihood. In our case, we consider equal probability of births and deaths for simplicity (except at the boundaries \(p=1\) and \(p=P_{\max}\)). The acceptance probability of removing an existing component is computed similarly to maintain detailed balance, inverting the fractions in the expression above.

This is already a rather manageable expression that can be implemented efficiently, but we can introduce another simplification: the proposal distribution can be chosen to match the prior distribution, so that the corresponding terms cancel out. We adopt this formulation in the functional regression methods in Chapter~\ref{ch:functional-regression}. For the functional testing method in Chapter~\ref{ch:functional-testing} we use a uniform proposal distribution on \([0,1]\) for the new parameter \(t^*\), which is then inserted into the ordered vector \(\tau\).  Nonetheless, in real-world scenarios one could consider more sophisticated proposal distributions that might better explore the parameter space; see \citet{davies2023transport} for some interesting ideas.

\section{Affine-invariant ensemble samplers}\label{sec:affine-invariant-samplers}

An interesting and often desirable property of regular \acs{MCMC} sampling algorithms is that they be \textit{affine-invariant}, which informally means that they regard two distributions that differ in an affine transformation, say \(\pi(x)\) and \(\pi_{A, b}(Ax + b)\), as equally difficult to sample from. This is useful when one is working with very asymmetrical or skewed distributions, for an affine transformation can turn them into ones with simpler shapes. Generally speaking, a \acs{MCMC} algorithm can be described through a function \(M\) as \(\Lambda(t+1)=M(\Lambda(t), \xi(t), \pi)\), where \(\Lambda(t)\) is the state of the chain at instant \(t\), \(\pi\) is the objective distribution, and \(\xi(t)\) is a sequence of i.i.d.\ random variables that represent the random behavior of the chain. With this notation, the affine-invariance property can be characterized as 
\[
  M(A\lambda+b, \xi(t), \pi_{A,b}) = AM(\lambda, \xi(t), \pi) + b,
\]
for all \(A,b\) and \(\lambda\), and almost all \(\xi(t)\). This means that if we fix a random generator and run the algorithm twice, one time using \(\pi\) and starting in \(\Lambda(0)\) and a second time using \(\pi_{A,b}\) with initial point \(\Gamma(0)=A\Lambda(0)+b\), then \(\Gamma(t)=A\Lambda(t)+b\) for all \(t\). In \citet{goodman2010ensemble} the authors consider an ensemble of samplers with the affine invariance property. Specifically, they work with a set \(\Lambda=(\Lambda_1, \dots, \Lambda_L)\) of walkers, where \(\Lambda_l(t)\) represents an individual chain at time \(t\). At each iteration, an affine-invariant transformation is used to find the next point, which is constructed using the current values of the rest of the walkers (similar to Gibb's algorithm), namely the complementary ensemble
\[
  \Lambda_{-l}(t) = \{\Lambda_1(t+1), \dots, \Lambda_{l-1}(t+1), \Lambda_{l+1}(t), \dots, \Lambda_L(t)\}, \quad l=1,\dots, L.
\]

To maintain the affine invariance and the joint distribution of the ensemble, the walkers are advanced one by one following a Metropolis--Hastings acceptance scheme. The authors consider mainly two types of moves.

\paragraph{Stretch move} For each walker \(1\leq l \leq L\) another walker \(\Lambda_j \in \Lambda_{-l}(t)\) is chosen at random, and the proposal is independently constructed as
\[
  \Lambda_l(t) \to \Gamma_s = \Lambda_j + Z_s(\Lambda_l(t) - \Lambda_j),
\]
where \(Z_s\) is a random variable with density \(g(z)\) satisfying the symmetry condition \(g(z^{-1})=zg(z)\). In particular, the suggested density is
\begin{equation}\label{eq:stretch-move-density}
  g(z) \propto \begin{cases}
    \frac{1}{\sqrt{z}}, & \text{if } z \in [a^{-1}, a], \\
    0,                  & \text{otherwise.}
  \end{cases}, \quad a > 1.
\end{equation}
Supposing \(\R^D\) is the state space, the corresponding acceptance probability (chosen so that the detailed balance equations are satisfied) is
\[
  \alpha_{\text{stretch}} = \min\left\{1, \, Z_s^{D-1}\frac{\pi(\Gamma_s)}{\pi(\Lambda_l(t))}\right\}.
\]

\paragraph{Walk move} For each walker \(1\leq l \leq L\) a random subset \(S_l \subseteq \Lambda_{-l}(t)\) with \(|S_l| \geq 2\) is selected, and the proposed move is
\[
  \Lambda_l(t) \to \Gamma_w = \Lambda_l(t) + Z_w,
\]
where \(Z_w\) is a normal variable with mean zero and the same covariance as the empirical covariance of all walkers in \(S_l\). The acceptance probability in this case is just the Metropolis ratio, i.e., 
\[
  \alpha_{\text{walk}} = \min\left\{1,\, \frac{\pi(\Gamma_w)}{\pi(\Lambda_l(t))}\right\}.
\]

From a computational perspective, the Python library \slsc{emcee}  provides a parallel implementation of this algorithm \citep{foreman2013emcee}. The idea is to divide the ensemble \(\Lambda\) into two equally-sized subsets \(\Lambda^{(0)}\) and \(\Lambda^{(1)}\), and then proceed on each iteration in the following alternate fashion:
\begin{enumerate}
  \item Update all walkers in \(\Lambda^{(0)}\) through one of the available moves explained above, using \(\Lambda^{(1)}\) as the complementary ensemble.
  \item Use the new values in \(\Lambda^{(0)}\) to update \(\Lambda^{(1)}\).
\end{enumerate}
In this way the detailed balance equations are still satisfied, and each of the steps can benefit from the computing power of an arbitrary number of processors (up to \(L/2\)).  

\section{Reversible jump implementation}

For the computational implementation of our Bayesian methods we chose the Python library \slsc{Eryn} \citep{karnesis2023eryn}. This package is a general-purpose suite of \acs{MCMC} methods which is reliable, easy to use and performs well in a wide class of problems. It is an enhancement of the \slsc{emcee} library that implements affine-invariant ensemble samplers with a \acs{RJMCMC} sampling scheme, along with a few key improvements. Every walker in the ensemble maintains a set of up to \(P_{\max}\) active components, each storing one coordinate \((\beta_j, s_j) \in \R\times \mathcal S\) in the functional regression case (along with the common fixed-dimension variables \(\alpha\) and \(\sigma^2\)), or just \(s_j\in\mathcal S\) in the functional testing case. 

Moreover, this library implements \textit{parallel tempering}, which is a mechanism to increase the efficiency with which the sampler explores the parameter space \citep{hukushima1996exchange}. The basic idea is to consider a set of Markov chains in parallel, each one sampling from a transformed posterior distribution with temperature \(T\geq 1\) given by 
\[
  \Pi_n^{(T)}(\theta_p\mid \text{data}) = \Pi(\theta_p)L(\text{data}\mid \theta_p)^{1/T}.
\] 
In this way, the posterior is smoothed out by reducing the contrast between areas of high and low likelihood. In practice, these chains periodically exchange information, with the swaps controlled by an acceptance probability that maintains detailed balance, and ultimately we are only interested on the cold chain (\(T=1\)). Figure~\ref{fig:tempered-posterior-p} shows the posterior distribution of the number of components \(p\) for each temperature in an example case.

\begin{figure}[t]
  \myfloatalign
  \includegraphics[width=.99\textwidth]{reg_analysis_tempered_posterior_p}
  \caption[Example of tempered posterior distribution]{Example of tempered posterior distribution of \(p\). We are only interested in the cold chain (\(T=1\)), but by allowing different temperatures we increase the exploration of the parameter space, periodically transferring some of this information to the cold chain.}\label{fig:tempered-posterior-p}
\end{figure}

The full sampling procedure can be summarized as follows.
\begin{enumerate}
  \item \slsc{Initialize} each of the \(W\) walkers with initial states \(\theta_{p_w}\) across all temperature levels. Ensure each walker has at least \(p_{\min}\) active components and at most \(P_{\max}\).
  \item \slsc{For each iteration} \(r=1,\dots, R\):
  \begin{enumerate}
    \item For each walker, propose new values for the existing parameters (without changing the dimension) and accept/reject.
    \item For each walker, propose a birth or death move and accept/reject.
    \item Propose temperature swaps between adjacent chains and accept/reject.
  \end{enumerate}
  \item \slsc{Collect} the posterior samples \(\{\theta^{(r)}\}_{r=1}^R\) from the cold chain (after burn-in).
\end{enumerate}

\subsection{Moves}

 As with any \acs{MCMC} method, the Markov chains are advanced iteratively through a set of moves. To generate new samples, the \acs{RJMCMC} method considers \textit{within-model} moves (perturbing the current parameter values without changing the dimension) and \textit{between-model} moves (increasing or decreasing the dimension). The former are implemented through minor modifications of the standard Metropolis--Hastings algorithm \citep{brooks2011handbook}, while the latter are generated by the reversible jump scheme explained at the start of this chapter.
 
Regarding the within-model moves, for the parameters that are common to all sub-models (i.e.\ \(\alpha\) and \(\sigma^2\) in the functional regression case), we use the stretch move described in Section~\ref{sec:affine-invariant-samplers}. For the parameters that change with the dimension (\(b\) and \(\tau\)), we use a variant known as the \textit{group stretch move}. This move was designed as an extension of the original stretch move to handle reversible jump setups. The main difference is that the random walker \(\Lambda_j\) used to advance the chain is selected from a stationary group that does not change for several iterations (see Section~3.1 in \citealp{karnesis2023eryn} for more information). In both moves, the key scaling parameter in~\eqref{eq:stretch-move-density} starts with a value of \(a=2\), and is changed dynamically to guide the sampler towards an acceptance rate of about \(20\%-30\%\), which is the range usually recommended in the literature \citep[e.g.][]{rosenthal2011optimal}.

\subsection{Initial values and hyperparameters}

We need to specify the initial values for the parameters of all the chains in our sampler. In general, we set these values by sampling from the prior distribution of the corresponding parameters. However, in the functional linear regression case the prior on \((\alpha, \sigma^2)\) is improper, so we use ad-hoc weakly informative distributions for the initial values instead. For \(\alpha\) we consider a normal distribution with mean zero and standard deviation \(10|\bar{Y}_{\text{scaled}}|\), where \(Y_{\text{scaled}}\) is the version of the original response data scaled to have standard deviation unity. For \(\sigma^2\) we use an inverse-gamma distribution with shape parameter \(\delta=2\) and scale parameter \(\xi=\hat\sigma^2_Y/\var(Y)\), where \(\hat \sigma^2_Y\) is a rough estimate of an acceptable error in the scale of \(Y\). This estimation is done is practice as two order of magnitudes less than \(|\bar{Y}|\).

One benefit of the reversible jump approach is that the algorithm only requires the specification of a few hyperparameters, irrespective of the underlying dimension. This contrasts to, say, the \(O(D^2)\) degrees of freedom corresponding to the covariance matrix of a \(D\)-dimensional jump distribution in Metropolis--Hastings. Some relevant hyperparameters include the burn-in period for the chains (the number of initial samples discarded), the number of actual steps, the number of chains, and the number of temperatures for parallel tempering. With sufficient computing power we could perform a grid search to find the best values for these hyperparameters, but we decided to use a fixed set of values due to execution time constraints.

\section{Label switching}

A well-known issue that arises when using \acs{MCMC} methods in finite mixture models such as the ones proposed in this work is \textit{label switching}, which in short refers to the lack of identifiability of the components of the model caused by their interchangeability. This can happen when the likelihood and the prior are symmetric with respect to the ordering of some parameters. This is the case of  \(b\) and \(\tau\) in the functional regression models, since \(L(Y|X,\theta)=L(Y|X, \theta[\nu])\) for any permutation \(\nu\) that rearranges the indices \(j=1,\dots, p\). Thus, since the components are arbitrarily ordered, they may be inadvertently exchanged from one iteration to the next in a \acs{MCMC} algorithm. This can cause nonsensical answers when summarizing the marginal posterior distributions of the parameters to perform inference, as different labelings might be mixed on each component \citep{stephens2000dealing}. This is primarily the reason why we do not directly use summaries of the posterior distribution of the individual parameters in our prediction methods.

Moreover, the use of transdimensional samplers exacerbates this problem, since the change in dimension can further disrupt the internal ordering of the components \citep[see][]{roodaki2014relabeling}. However, this phenomenon is perhaps surprisingly a condition for the convergence of the \acs{MCMC} method: as pointed out by many authors \citep[e.g.][]{celeux2000computational}, a lack of switching would indicate that not all modes of the posterior distribution were being explored by the sampler. For this reason, many ad-hoc solutions revolve around post-processing and relabeling the samples to eliminate the switching effect, but they generally do not prevent it from happening in the first place.

The most straightforward solutions consist on imposing an artificial identifiability constraint on the parameters to break the symmetry of their posterior distributions; see \citet{jasra2005markov} and references therein. A common approach that seems to work well is to simply enforce an ordering in the parameters in question, which in our case would mean requiring for example that \(\beta_i < \beta_j\) for \(i < j\), or the analogous with the times in \(\tau\). We have implemented a variation of this method described in \citet{simola2021approximate}, which works by post-processing the samples and relabeling the components to satisfy the order constraint mentioned above, choosing either \(b\) or \(\tau\) depending on which set of ordered parameters would produce the largest separation between any two of them (suitably averaged across all iterations of the chains). This is an area of ongoing research, and thus there are other, more complex relabeling strategies, both deterministic and probabilistic. A summary of several such methods can be found for example in \citet{sperrin2010probabilistic} or \citet{rodriguez2014label}.

In the testing case of Chapter~\ref{ch:functional-testing}, however, label switching is not a practical concern for two reasons. First, as noted in Section~\ref{sec:rkhs-test}, we impose an ordering on the time instants, removing the symmetry and identifying a unique labeling. Second, and more importantly, most posterior quantities of interest are identifiable in the sense that they depend on the mean function parametrization \(\mu_\theta(\cdot) = \sum_{j} \beta_j K(t_j, \cdot)\), which is invariant under relabeling, so the functionals we report would be unchanged even if we did not impose an ordering.

\section{Practical notes for implementation}

We comment briefly on a few implementation suggestions aimed at improving the computational efficiency of the \acs{RJMCMC} algorithm:

\begin{enumerate}
  \item Use Cholesky decompositions to avoid computing expensive matrix inverses.
  \item Use log-formulas for most of the probability arithmetic, employing the Python built-in functions \texttt{logaddexp(x,y)=log(exp(x)+exp(y))} and \texttt{log1p(x)=log(1+x)} to compute the relevant expressions.
  \item Store reusable values per \acs{RJMCMC} step for later computations, building a sort of cache memory.
  \item Use vectorized operations to speed up computations.
\end{enumerate}
